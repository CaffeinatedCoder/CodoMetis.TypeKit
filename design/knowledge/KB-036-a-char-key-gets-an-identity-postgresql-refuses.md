# KB-036. A plain `char` key gets an identity column on Npgsql, which PostgreSQL refuses

With no configuration, an entity keyed by a `char` is created by Npgsql's EF provider as
`"Id" character(1) GENERATED BY DEFAULT AS IDENTITY`, and `EnsureCreated` fails with PostgreSQL's
`22023`: an identity column's type must be `smallint`, `integer` or `bigint`. It is the provider's choice for
the plain type that PostgreSQL refuses, which [decision 63](../adr/0063-char-keys-application-assigned-ulong-documented.md)
cites for keys over `char`.
